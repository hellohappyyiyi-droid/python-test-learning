原理｜把人工比较变成自动检查

以前你调用 get_status(0)，用眼睛看输出。现在测试代码调用它，再用 assert 比较实际与预期。pytest 是寻找、执行测试并汇总结果的工具；它不替你决定业务规则。

actual = get_status(0)
assert actual == "PASS"
架构｜业务代码和测试代码分开

项目根目录放 report_utils.py；tests/test_report_utils.py 专门检查它。测试文件导入业务函数，pytest 在项目根目录启动。测试不是生产逻辑，不能修改结果让测试“通过”。

from report_utils import get_status

def test_zero_is_pass():
    actual = get_status(0)
    assert actual == "PASS"
数据流｜发现、调用、断言、汇总

python -m pytest 使用当前 Python 环境中的 pytest。它默认发现 test_*.py 或 *_test.py，再发现 test_ 开头的函数，依次执行并汇总。安装 pytest 和执行 pytest 应使用同一 Python 环境。

python -m pip install pytest
python -m pytest -q
接口｜输入、实际结果和预期结果

测试用例由准备输入、调用被测函数、断言预期组成。expected 应来自约定，不能根据 actual 动态生成，否则错误行为也可能通过。assert 为 False 时抛出 AssertionError。

def test_positive_is_fail():
    loss = 3
    actual = get_status(loss)
    expected = "FAIL"
    assert actual == expected
定位｜先分清没找到和执行失败

no tests ran：先看文件名、函数名、目录；ModuleNotFoundError：看启动目录、环境和导入；AssertionError：已经执行到比较，核对实际值与契约。

python -m pytest tests/test_report_utils.py -vv
最小修改与 Git｜修完再验证

先用失败用例复现，再修业务代码，最后运行所有相关测试。git diff 查看修改；git diff --cached 查看暂存内容。不要直接把预期改成错误的实际输出。

原理｜流程相同，数据不同

不必复制七个函数。parametrize 告诉 pytest：用同一段测试逻辑，分别代入多组输入和预期；每组仍是独立用例。

import pytest
from report_utils import get_status

@pytest.mark.parametrize("loss, expected", [
    (0, "PASS"),
    (2, "FAIL"),
    (-1, "ERROR"),
])
def test_status(loss, expected):
    assert get_status(loss) == expected
架构与数据流｜表头和行

"loss, expected" 是两列名称，对应测试函数两个参数；每个元组是一行。第一行传 loss=0、expected="PASS"。下一行重新执行测试。装饰器需紧接测试函数。

接口｜不要混淆名称与值

参数名要匹配；一组有两列就必须给两个值。ids 给数据组易读名字，帮助在失败报告中定位具体场景。

@pytest.mark.parametrize("loss, expected", [
    (0, "PASS"),
    (True, "ERROR"),
], ids=["zero", "bool_true"])
def test_status(loss, expected):
    assert get_status(loss) == expected
设计｜等价类与边界

0 是零丢包边界；小正数和普通正数应 FAIL；负数、字符串、None、True、False 分别覆盖不同非法类别。0.0 和 0.1 检查浮点行为。本课程不设置 100 上限；不要自行改变既有需求。

定位｜区分表格错误与业务错误

参数个数不匹配可能在收集阶段报错，还未执行业务；只有某组断言失败，则核对该输入的业务规则与实际输出。不要把错误预期改到能通过为止。

python -m pytest tests/test_report_utils.py -vv
原理｜返回和抛出是两条路径

get_status(-1) 返回 ERROR，是正常返回一个状态字符串；open 不存在的文件抛 FileNotFoundError，会沿调用链向外寻找 except。两者的测试写法不同。

assert get_status(-1) == "ERROR"

with pytest.raises(FileNotFoundError):
    load_report(missing_path)
