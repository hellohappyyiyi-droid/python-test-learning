沿用现有业务契约

统一业务契约：get_status(loss) 对数字 0 返回 PASS，对正数返回 FAIL；负数、布尔、字符串、None 等非法输入返回 ERROR。沿用你已有分析器的约定，不增加 100 上限。文件读取异常由读取函数抛出，批量层负责捕获并计入 ERROR。

原理 → 架构 → 数据流 → 接口 → 定位与修改

原理｜流程相同，数据不同

不必复制七个函数。parametrize 告诉 pytest：用同一段测试逻辑，分别代入多组输入和预期；每组仍是独立用例。

import pytest
from report_utils import get_status

@pytest.mark.parametrize("loss, expected", [
    (0, "PASS"),
    (2, "FAIL"),
    (-1, "ERROR"),
])
def test_status(loss, expected):
    assert get_status(loss) == expected
架构与数据流｜表头和行

"loss, expected" 是两列名称，对应测试函数两个参数；每个元组是一行。第一行传 loss=0、expected="PASS"。下一行重新执行测试。装饰器需紧接测试函数。

接口｜不要混淆名称与值

参数名要匹配；一组有两列就必须给两个值。ids 给数据组易读名字，帮助在失败报告中定位具体场景。

@pytest.mark.parametrize("loss, expected", [
    (0, "PASS"),
    (True, "ERROR"),
], ids=["zero", "bool_true"])
def test_status(loss, expected):
    assert get_status(loss) == expected
设计｜等价类与边界

0 是零丢包边界；小正数和普通正数应 FAIL；负数、字符串、None、True、False 分别覆盖不同非法类别。0.0 和 0.1 检查浮点行为。本课程不设置 100 上限；不要自行改变既有需求。

定位｜区分表格错误与业务错误

参数个数不匹配可能在收集阶段报错，还未执行业务；只有某组断言失败，则核对该输入的业务规则与实际输出。不要把错误预期改到能通过为止。
