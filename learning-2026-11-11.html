每次一个概念，按顺序学习

1｜为什么需要fixture

多个测试需要相同的准备步骤。fixture把准备与清理集中管理，测试函数只负责调用业务和断言。下面是教学示例，不是BVT源码。

import pytest

@pytest.fixture
def report():
    return {"loss": 0}

def test_loss(report):
    assert report["loss"] == 0
2｜按名称请求，不是手动调用

pytest看到测试参数report，先寻找同名fixture，再执行它，把返回值传给测试。装饰器注册fixture；测试参数接收的是数据，不是函数本身。

@pytest.fixture
def report():
    print("准备")
    return {"loss": 0}

def test_loss(report):
    print("使用", report)
    assert report["loss"] == 0
3｜yield把生命周期分成两段

先执行yield之前的准备；yield把对象交给测试并暂停；测试结束后继续执行yield之后的清理。测试断言失败，通常仍会执行已到达yield的fixture清理。若准备在yield之前抛异常，该fixture的yield后代码不会执行；进程被强杀也不能保证清理。

@pytest.fixture
def report():
    print("准备")
    yield {"loss": 0}
    print("清理")

def test_loss(report):
    print("测试")
    assert report["loss"] == 0

# python -m pytest -s -v test_fixture.py
4｜scope决定复用多久

默认function：每条测试重新准备、各自清理。module：同一模块内复用一次，模块相关测试结束后清理。共享可变字典可能让用例互相影响。初学优先默认function；不要为省代码随意扩大scope。

@pytest.fixture(scope="function")
def report():
    return {"loss": 0}

# 两条测试各得到一份新字典
# class：类；module：模块；session：本次运行
5｜conftest共享，tmp_path隔离文件

公共fixture放在tests/conftest.py，可供该目录及子目录的测试自动发现，测试中按名称请求即可；业务函数仍需正常导入。tmp_path是pytest内置fixture，每条测试获得独立的pathlib.Path目录，不需要你自己定义。它不保证测试后立即删除目录，pytest会按保留策略管理。

import json
import pytest

@pytest.fixture
def report_path(tmp_path):
    path = tmp_path / "report.json"
    path.write_text('{"loss": 0}', encoding="utf-8")
    return path

def test_read(report_path):
    data = json.loads(report_path.read_text(encoding="utf-8"))
    assert data["loss"] == 0
6｜先看执行阶段，再定位

fixture找不到：核对名字与conftest目录；setup报错：先修准备步骤，测试体可能尚未运行；断言失败：核对业务或预期；teardown报错：核对清理。需要看print时用-s，不把没有显示打印误认为fixture没执行。
