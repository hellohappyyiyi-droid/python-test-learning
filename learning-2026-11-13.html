沿用现有业务契约

统一业务契约：get_status(loss) 对数字 0 返回 PASS，对正数返回 FAIL；负数、布尔、字符串、None 等非法输入返回 ERROR。沿用你已有分析器的约定，不增加 100 上限。文件读取异常由读取函数抛出，批量层负责捕获并计入 ERROR。

原理 → 架构 → 数据流 → 接口 → 定位与修改

原理｜返回和抛出是两条路径

get_status(-1) 返回 ERROR，是正常返回一个状态字符串；open 不存在的文件抛 FileNotFoundError，会沿调用链向外寻找 except。两者的测试写法不同。

assert get_status(-1) == "ERROR"

with pytest.raises(FileNotFoundError):
    load_report(missing_path)
架构｜哪层负责处理异常

load_report 只读单个 JSON 并返回字典，让异常向外传播。批量层统计错误并继续下一条。同一个文件缺失，在读取层测试预期抛出，在批量层测试预期 ERROR 计数，取决于接口职责。

import json

def load_report(path):
    with open(path, encoding="utf-8") as file:
        return json.load(file)
数据流｜raises 是一个检查范围

先进入 with，执行其下缩进的受测代码。若抛出预期异常，pytest 把它记为符合预期并允许继续；若没有异常，报告 DID NOT RAISE；类型不匹配则该测试不能通过。

def test_missing(tmp_path):
    path = tmp_path / "missing.json"
    with pytest.raises(FileNotFoundError):
        load_report(path)
接口｜异常类型要具体

损坏 JSON 对应 json.JSONDecodeError；缺字典键对应 KeyError。with 中尽量只放真正应抛出的操作，避免准备步骤先抛出相同异常导致误通过。

with pytest.raises(json.JSONDecodeError):
    load_report(broken_path)
定位｜先读最后一行，再看调用链

AssertionError 看比较值；DID NOT RAISE 看本该抛异常的操作；setup ERROR 看 fixture 准备；解析错误核对原始文本与解析输出；判定错误核对解析数字与规则。

python -m pytest tests/test_report_utils.py -x -vv
最小修改｜别用 except Exception 吞掉证据

先定位到负责层，捕获你明确能够处理的异常。让不可预期的程序错误暴露，别为了全绿把任意异常都计入成功。修复后覆盖正常和异常路径。
