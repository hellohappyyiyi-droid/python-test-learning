01｜Python 工程基础：从一条测试报告到统计结果

原理与数据流

读取文件 → JSON 反序列化 → 提取字段 → 校验数据类型 → 计算状态 → 汇总结果。每一层只处理自己负责的问题。

文件路径
  ↓
json.load(file)
  ↓
report["loss"]
  ↓
校验 loss 类型和取值
  ↓
PASS / FAIL / ERROR
  ↓
统计并输出

异常边界

  • FileNotFoundError：目标文件不存在。
  • json.JSONDecodeError：文件内容不是合法 JSON。
  • KeyError：字典缺少指定字段。
  • TypeError / ValueError：数据类型或取值不符合约定。
单条报告异常：记录 ERROR 后继续处理下一条。目录不存在、配置缺失等初始化问题：可能导致整个任务无法启动，不能简单吞掉异常。

数据校验陷阱

if isinstance(loss, (int, float)):
    ...

Python 中 bool 是 int 的子类，所以 True 也会通过上面的类型检查。需要先排除布尔值，再检查数值类型。

if isinstance(loss, bool):
    # 非法
    ...
elif not isinstance(loss, (int, float)):
    # 非法
    ...

模块与入口

工具函数放在模块中，入口文件负责组织流程。if __name__ == "__main__": 用来区分“直接运行文件”和“被其他模块导入”。

日志

logging 用于记录运行过程。INFO 记录正常阶段和结果，WARNING 记录可恢复异常，ERROR 记录失败原因。日志信息应能回答：什么时候、处理什么对象、发生了什么。

02｜Pytest：让测试代码自动执行和判定

测试发现规则

默认将文件名写成 test_*.py 或 *_test.py，测试函数通常以 test_ 开头。这样 Pytest 才能按约定发现用例。

断言 assert

def test_ping_status():
    result = run_ping()
    assert result["status"] == "ok"

测试函数调用被测功能，assert 比较实际结果和预期结果。条件为 False 时，测试失败并输出断言信息。

fixture

import pytest

@pytest.fixture
def sample_report():
    return {"loss": 0}

def test_report(sample_report):
    assert sample_report["loss"] == 0

fixture 提供测试前置资源或数据。测试函数把 fixture 名称写为参数，Pytest 会注入对应返回值；需要清理资源时可使用 yield。

参数化

@pytest.mark.parametrize(
    "loss, expected",
    [(0, "PASS"), (1, "FAIL")]
)
def test_get_status(loss, expected):
    assert get_status(loss) == expected

同一测试逻辑使用多组输入和预期结果重复执行，减少重复代码。参数化数据要覆盖正常、边界和非法输入。

临时文件与异常

tmp_path 是 Pytest 提供的临时目录 fixture，适合创建测试文件，避免污染真实项目目录。对于预期抛出的异常，可使用 pytest.raises(...) 验证。

03｜BVT 源码定位：不要只盯着最后一行

先画调用链

Test Case
   ↓
Workflow / Service
   ↓
Adapter / Tool
   ↓
系统命令或设备接口
   ↓
原始结果
   ↓
解析与标准化
   ↓
PASS / FAIL 判定
   ↓
报告输出

定位顺序

  1. 明确现象：输入是什么、实际输出是什么、预期是什么。
  2. 从日志找到关键函数、参数和值。
  3. 沿调用链向下追踪，找到第一处数据偏差。
  4. 区分采集/解析错误与业务判定错误。
  5. 分析调用方影响，只做最小修改。
  6. 设计正常、异常、边界回归。
  7. 用 Git 检查修改范围和差异。
例如“发 4 收 3，却判 PASS”：先确认原始 ping 输出和解析后的 received，再检查 success 的生成位置，最后检查上层是否直接沿用了 success。不能看到报告 PASS 就直接改报告层。

参数传递

如果 Service 收到 timeout=5，调用 Adapter 时却没有传递该参数，Adapter 可能使用自己的默认值。排查时要逐层记录：调用方传入什么、被调用方收到什么、默认值在哪里生效。

Git 验证

git status
git diff
git add path/to/target_file.py
git diff --cached
git commit -m "fix: correct ping result parsing"

先看工作区变化，再定向暂存目标文件，检查暂存区差异，确认没有混入无关文件后提交。
