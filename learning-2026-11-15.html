原理 → 架构 → 数据流 → 接口 → 定位与修改

原理｜测试的准备助手

fixture 负责准备测试需要的数据或资源。例如先创建报告文件再让测试读取。@pytest.fixture 把函数注册为准备助手；测试参数写它的名字，pytest 帮你调用并传值。

@pytest.fixture
def report_data():
    return {"loss": 0}

def test_data(report_data):
    assert report_data["loss"] == 0
架构｜谁调用谁

pytest 调用 fixture，接收其 return，再把返回值传给测试函数。同名的 fixture 函数和测试参数分属不同作用域：测试函数内部 report_data 指向字典，不是准备函数本身。不需要自己调用 fixture。

数据流｜yield 前后是生命周期

yield 之前准备；yield 的值传入测试；测试结束后恢复 fixture，执行 yield 后清理。用例断言失败通常仍会清理。若准备在到达 yield 前失败，后面的代码不会自动执行；不能把它说成无条件保证。

@pytest.fixture
def connection():
    conn = open_connection()
    yield conn
    conn.close()
接口｜scope 决定共享时长

function 默认每个测试一次；class 每个类、module 每个模块、package 每个包、session 每轮运行一次。共享越久越要防止可变状态污染。先用 function，确有昂贵准备且隔离可控时才扩大范围。

文件接口｜tmp_path 和 JSON

tmp_path 是内置 fixture，值为 pathlib.Path 独立临时目录；你仍需创建文件。路径拼接 / 不会创建文件。写 JSON 时用 json.dumps，明确 UTF-8。

def test_load(tmp_path):
    path = tmp_path / "report.json"
    path.write_text(json.dumps({"loss": 0}), encoding="utf-8")
    assert load_report(path) == {"loss": 0}
共享与定位｜conftest 和 autouse

把公共 fixture 放 tests/conftest.py，可供该目录及子目录内测试自动发现。autouse=True 表示作用范围内用例自动执行准备；要使用其返回值仍需声明参数。报 fixture not found 时查名字、作用范围和 conftest 位置。

原理｜返回和抛出是两条路径

get_status(-1) 返回 ERROR，是正常返回一个状态字符串；open 不存在的文件抛 FileNotFoundError，会沿调用链向外寻找 except。两者的测试写法不同。

assert get_status(-1) == "ERROR"

with pytest.raises(FileNotFoundError):
    load_report(missing_path)
架构｜哪层负责处理异常

load_report 只读单个 JSON 并返回字典，让异常向外传播。批量层统计错误并继续下一条。同一个文件缺失，在读取层测试预期抛出，在批量层测试预期 ERROR 计数，取决于接口职责。

import json

def load_report(path):
    with open(path, encoding="utf-8") as file:
        return json.load(file)
数据流｜raises 是一个检查范围

先进入 with，执行其下缩进的受测代码。若抛出预期异常，pytest 把它记为符合预期并允许继续；若没有异常，报告 DID NOT RAISE；类型不匹配则该测试不能通过。

def test_missing(tmp_path):
    path = tmp_path / "missing.json"
    with pytest.raises(FileNotFoundError):
        load_report(path)
接口｜异常类型要具体

损坏 JSON 对应 json.JSONDecodeError；缺字典键对应 KeyError。with 中尽量只放真正应抛出的操作，避免准备步骤先抛出相同异常导致误通过。

with pytest.raises(json.JSONDecodeError):
    load_report(broken_path)
原理与架构｜把各层分别验清

get_status 负责单个 loss；load_report 负责单文件解析；summarize(folder) 遍历 *.json 并汇总。读取异常和缺字段在批量层转为 ERROR，单条失败不终止整批。教学案例不是 BVT 真实源码。

接口契约｜汇总的守恒关系

返回字典包含 PASS、FAIL、ERROR、Total 四个整数。Total 每处理一个目标 JSON 文件加一；无论成功或错误，都归入且仅归入一个状态，因此三种状态之和等于 Total。空目录全部为 0；非 JSON 文件不计入。

{"PASS": 2, "FAIL": 2, "ERROR": 4, "Total": 8}
